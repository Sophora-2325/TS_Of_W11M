日期：2026-10-26（Asia/Shanghai）。代码基线：`e7ffde5`，版本 `0.1.0`。

**首批修复更新：BUG-01、BUG-02、BUG-03 已实现修复，20 项正式模块测试通过。** 当前验证、桌面操作限制和剩余问题见 [首批修复验证](首批修复验证.md)。下文保留初次审查基线及当时的证据，不能把其中的旧代码行为视为修复后的现状。

## 2. 已确认问题

P1 表示应优先修复的主要流程/结果正确性问题；P2 表示在特定条件下影响使用；P3 表示较低频边界问题。

### BUG-01 · P1 · “重新框选”关闭浮窗后没有打开框选层

- **复现**：在正式构建浮窗点击“重新框选”。本次在当前源码构建上重复出现。
- **实际结果**：窗口列表只剩 `overlay`、`main`，且 `overlayVisible=false`，用户失去当前浮窗又没有获得选区。
- **根因**：[TranslationPopup.tsx:198](D:/STOR/src/components/TranslationPopup.tsx:198) 先等待当前 WebView `close()`，再调用 `reopen_overlay`；页面销毁后后续 JavaScript 无法可靠继续。后端 [lib.rs:255](D:/STOR/src-tauri/src/lib.rs:255) 本身已经负责关闭旧浮窗。
- **修复方向**：由仍存活的前端直接调用后端重选命令，让后端统一完成关闭浮窗和打开框选层。
- **证据**：[reselect-test.txt](evidence/reselect-test.txt)。对照测试中，从仍存活的设置页调用同一后端入口可以打开框选层，默认全局快捷键也可以打开。

### BUG-02 · P1 · 无效快捷键保存失败后旧热键消失，错误配置仍被保存

- **复现**：调用设置保存，把 `Ctrl+Shift+T` 改为 `NotAValidHotkey`。
- **实际结果**：保存返回错误，但内存配置已变为无效值，旧热键的 `is_registered` 返回 `false`。
- **根因**：[lib.rs:76](D:/STOR/src-tauri/src/lib.rs:76) 先写文件和内存，再注册热键；[lib.rs:529](D:/STOR/src-tauri/src/lib.rs:529) 先注销所有旧热键再尝试新值，失败时没有回滚。
- **影响**：当前会话失去热键；错误配置留到下次启动时，初始化中的 `register_hotkey(...)?` 会使 setup 失败，并触发后续 `expect` 退出。这一下次启动后果由源码确认，本次没有故意留下错误配置并重启。
- **修复方向**：解析、冲突检查、注册与配置持久化需要可回滚；失败保留旧绑定和旧配置。
- **证据**：[hotkey-test.txt](evidence/hotkey-test.txt)。测试 `finally` 已恢复 `Ctrl+Shift+T`，随后实际快捷键唤起成功。这里临时修改的是应用实际配置，不依赖 APPDATA 环境变量实现隔离。

### BUG-03 · P1 · 中文字符跨网络分片时变成乱码

- **复现**：本机 SSE 服务器把“你”的 UTF-8 三字节拆到两个 HTTP 数据块中。
- **实际结果**：期望 `你好`，得到 `���好`。
- **根因**：[deepseek.rs:142](D:/STOR/src-tauri/src/translate/deepseek.rs:142) 对每个任意网络字节块单独执行 `String::from_utf8_lossy`。字节块不保证落在字符边界，不完整字符被提前替换。
- **影响**：翻译和查词共用该解析器，乱码还可能进入缓存。
- **修复方向**：保留原始字节，按完整 SSE 行或使用增量 UTF-8 解码后再解析 JSON。
- **证据**：独立测试 `utf8_split_should_preserve_text` 稳定失败；完整中文 SSE 对照测试通过。

### BUG-04 · P2 · 缺少结束标记的半截译文被当成成功并可缓存

- **复现**：模拟服务器返回一条 `partial` 内容事件，随后正常结束 HTTP body，但不发送 `[DONE]` 或完整结束状态。
- **实际结果**：返回 `Ok("partial")`，没有提示结果不完整。
- **根因**：[deepseek.rs:152](D:/STOR/src-tauri/src/translate/deepseek.rs:152) 只跳过 `[DONE]`，不记录是否完整结束；函数退出时只检查文本是否非空。[lib.rs:182](D:/STOR/src-tauri/src/lib.rs:182) 会缓存这个成功结果。
- **限定**：不是所有断网都会静默成功；底层返回传输错误时现有代码会报错。这里复现的是“HTTP 正常 EOF，但 SSE 缺少完成信息”。
- **修复方向**：验证流的完成状态；不完整结果提示失败且不缓存。

### BUG-05 · P2 · 冻结截图超过 3 秒失效，OCR 改截当前覆盖层

- **复现**：让已缓存截图的捕获时间距离当前 4 秒，再尝试裁剪。
- **实际结果**：缓存返回 `None`；真实截图流程会回退到重新截图。
- **根因**：[screen.rs:9](D:/STOR/src-tauri/src/capture/screen.rs:9)、[screen.rs:58](D:/STOR/src-tauri/src/capture/screen.rs:58) 将冻结选区会话与 3 秒缓存 TTL 混用，而 [lib.rs:117](D:/STOR/src-tauri/src/lib.rs:117) 在 OCR 完成后才隐藏 overlay。
- **影响**：慢慢框选时不再使用原始干净截图，回退截图可能包含冻结图自身、遮罩、选区边框及识别状态提示，降低识别稳定性。不能据此声称所有超过 3 秒的选区都会识别失败；本次真实慢选仍成功识别了设置页标题。
- **修复方向**：冻结截图绑定选区会话，直到确认或取消才释放；实时截图路径需避免把 overlay 截入。

### BUG-06 · P2 · 截图缓存未验证显示器归属，可能返回另一块屏幕的图

- **复现**：合成缓存的显示器起点 `x=1920`，请求矩形却在 `x=2`。
- **实际结果**：仍返回裁剪图片，负相对坐标被钳制成 0。
- **根因**：[screen.rs:62](D:/STOR/src-tauri/src/capture/screen.rs:62) 没有先检查矩形是否属于缓存范围；关闭冻结后旧缓存也没有主动清空，而 OCR 仍总是传入缓存。
- **修复方向**：验证显示器/会话身份和完整矩形归属；关闭冻结时不得复用旧冻结图。
- **边界**：底层错误复用已由合成双屏坐标确认；未在真实多显示器上完成端到端复现。

### BUG-07 · P2 · 英文点选区丢失数字和下划线

- **复现**：输入 `Level 42 HP_100 gold: 50`。
- **实际结果**：点选区域显示为 `Level  HP gold: `，数字、下划线消失；原文文本框仍然完整，因此不能说发送给翻译接口的原文本身被删掉。
- **根因**：[InteractiveText.tsx:10](D:/STOR/src/components/InteractiveText.tsx:10) 正则只匹配 ASCII 字母、空白和非 word 字符，没有覆盖数字与 `_`。
- **修复方向**：分词必须无损保留每一个原始字符；不能点选的内容也要作为普通文本渲染。
- **证据**：[token-loss.png](evidence/token-loss.png)。点击 `gold` 本身可以正确选中。

### BUG-08 · P2 · 缺少 OCR 语言包时给出错误方向的提示

- **复现环境**：Windows 只报告 `zh-Hans-CN`。用合成图片显式选择英文或日文 OCR。
- **实际结果**：对应引擎创建失败；错误被吞掉后用户只会收到“未能识别出文字，请尝试扩大选区或手动输入”。
- **根因**：[windows_ocr.rs:118](D:/STOR/src-tauri/src/ocr/windows_ocr.rs:118) 忽略所有引擎错误；设置界面没有根据已安装语言包禁用或标识选项。
- **修复方向**：区分“语言包不可用”“截图/引擎失败”“确实无文字”，显示可操作的提示。
- **证据**：[rust-tests.txt](evidence/rust-tests.txt)。中文图片能识别；自动模式可用中文引擎读出英文样例，但不能据此认定英文引擎已安装。

### BUG-09 · P3 · 查词缓存键存在拼接碰撞

- **复现**：句子 `a::b`、词语 `c`，以及句子 `a`、词语 `b::c`，解释语言均为 `zh`。
- **实际结果**：两组不同输入都生成 `lookup::zh::a::b::c`。
- **根因**：[cache.rs:32](D:/STOR/src-tauri/src/cache.rs:32) 直接用未转义的 `::` 拼接可变文本。
- **修复方向**：使用结构化 tuple/序列化键或长度前缀；缓存也应纳入模型、提示词版本等影响输出的参数。
- **边界**：底层键碰撞已复现；示例第二组并非正常的“句中选词”，本次未证明该碰撞可由日常点词流程直接触发，因此列为低优先级。

## 3. 源码确认的缺点与尚待进一步复现的风险

以下不与上面的 9 项已复现问题混算。

1. **OCR 自动模式不是可靠的语种检测。** 所有非空结果固定评分 `0.8`，而选优只接受严格大于；实际是按 `en → ja → zh` 顺序保留第一个非空结果。多个语言包同时存在时，英语误识别有机会阻止中日文更合适的结果被采用。本机只有中文语言包，未测试多个引擎同时可用时的实际准确率。[windows_ocr.rs:91](D:/STOR/src-tauri/src/ocr/windows_ocr.rs:91)
2. **翻译/查词没有请求身份、取消与失效结果过滤。** 应用级 chunk 事件只带字符串，新 OCR、编辑原文、换选词后旧任务仍可能更新结果；关闭并新开浮窗也没有后端任务取消。本次合成事件观察到监听器会接收旧内容，但模拟请求拦截失效，未完成受控的并发请求端到端复现，不作为“已经稳定复现的真实网络串文 BUG”。[TranslationPopup.tsx:91](D:/STOR/src/components/TranslationPopup.tsx:91)
3. **未设置明确的请求/读流超时。** `Client::new()`、`.send()` 和持续读流没有应用自己的截止时间，也没有用户取消按钮。忙碌时又禁用了重选，异常网络可能长期影响窗口操作。[deepseek.rs:62](D:/STOR/src-tauri/src/translate/deepseek.rs:62)
4. **多显示器定位风险。** 浮窗坐标用 `.max(0)` 截断，负坐标的左侧/上侧屏幕会被错误移到非负区域；没有限制右边缘和下边缘；overlay 的缩放因子在移动到新显示器前获取，混合 DPI 环境需专项验证。本次只验证了当前屏幕 150% 缩放。[lib.rs:384](D:/STOR/src-tauri/src/lib.rs:384)、[lib.rs:446](D:/STOR/src-tauri/src/lib.rs:446)、[lib.rs:497](D:/STOR/src-tauri/src/lib.rs:497)
5. **缓存能力有限。** 仅在内存中，退出即丢失；缓存键不包括模型，换模型后可能仍返回旧模型结果；没有查看、清理缓存入口。
6. **UI 状态与可访问性。** “原文为空”报错在输入文字后仍保留；可点英文词用无键盘语义的 `span`；部分标签没有关联输入；长文本、窄窗口、输出长 URL 的布局缺少边界处理。设置面板中已配置只表示凭据存在，不等于 Key 有效或余额可用。
7. **配置与凭据维护。** 没有删除 Key 的入口和明确的 API 连通性检查；配置字段缺少集中校验，损坏配置回退默认值时缺少用户提示；`popupOpacity` 被读写但没有实际应用。
8. **质量保障缺口。** 原项目没有前端测试脚本，Rust 单测及文档测试均为 0；也没有本次能使用的既有端到端测试。当前构建会产生 5 条未使用代码警告。建议先为本报告的 P1/P2 问题补回归测试，再扩展复杂游戏与多屏测试。

## 5. 测试环境插曲与限制

- 用户反馈的 `localhost ERR_CONNECTION_REFUSED` 出现在本次直接使用 Cargo 构建并启动的测试程序；直接 Cargo 构建没有使用项目正式打包入口，仍加载开发地址。改按 README 的 Tauri 构建入口后，实际窗口恢复为 `http://tauri.localhost/`，且截图 OCR 链路成功。**这是本次测试启动方式错误，不计入软件 BUG。**
- 桌面启动工具曾打开 `D:\MyTests\stor.exe` 副本。之后关键功能复现使用主机明确启动的 `D:\STOR\src-tauri\target\release\stor.exe`，避免把副本问题当成当前源码问题。
- 一次尝试在真实浮窗里模拟翻译 IPC 的操作没有成功拦截请求，可能发出了一次真实 DeepSeek 合成文本请求。发现后立即终止了该测试进程；未完成成功链路，也没有证据确认费用为零。失败的拦截脚本已移除；`stale-translation.png` 来自这次不合格测试，不作为真实并发网络问题已复现的证据。独立 Rust SSE 测试仅连接本机。
- 未完成真实 API 的鉴权、余额、限流、模型差异和长期流式稳定性验证；未验证真实全屏游戏、HDR、游戏保护截图、多个显示器/混合 DPI、安装包安装卸载、所有托盘菜单和复制到剪贴板操作。
- `APPDATA` 环境变量不能作为 Windows Known Folder API 的可靠隔离手段。本次热键测试实际临时改动了配置，然后在 `finally` 恢复；后续实际快捷键测试成功。未修改已有 API Key。

## 6. 建议处理顺序

1. 先修 BUG-01、BUG-02、BUG-03：避免主要入口失效、配置导致无法启动，以及译文损坏。
2. 修复流结束校验与冻结会话缓存；为异步翻译、OCR 和查词增加请求身份及取消/超时。
3. 修复无损分词、语言包提示与多屏定位，补上以上场景的回归测试。
4. 再完善缓存维护、Key 管理、键盘操作和窄窗口布局。
