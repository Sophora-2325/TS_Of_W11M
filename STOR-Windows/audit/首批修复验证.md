# STOR 首批 3 项修复与验证

日期：2026-10-26。修复范围仅为原报告 BUG-01、BUG-02、BUG-03。版本仍为 0.1.0，配置 JSON 字段和 DeepSeek 请求/事件接口保持兼容。

## 修复内容

| 原问题 | 当前实现 | 验证 |
| --- | --- | --- |
| BUG-01 重新框选失效 | 前端只调用后端重选命令；后端先成功打开并聚焦选区，再关闭旧浮窗。打开错误会返回前端并保留浮窗；前端用同步 ref 和禁用状态阻止重复提交 | 正式程序中确认框选层可见、旧浮窗关闭；完成 OCR 后浮窗重建；再触发重选成功；同一事件轮连续触发两次按钮后状态正常；Esc 隐藏框选层 |
| BUG-02 热键保存破坏旧配置 | 新增统一热键事务、规范化键名、相同绑定不重新注册。先注册新键、原子写文件、注销旧键，最后提交内存；失败执行补偿并反馈回滚错误 | 模拟注册冲突、无效键、写盘失败、注销失败、补偿失败和启动异常均有正式模块测试；真实临时文件验证原子替换和失败保持旧内容 |
| BUG-03 流式中文乱码 | 字节缓冲到完整 SSE 行后才严格解码 UTF-8；未完成行等待下一块；EOF 截断或非法 UTF-8 报错，防止错误结果缓存 | 对中日文 SSE 在每个字节边界拆分、逐字节输入、JSON/换行拆分、CRLF、多事件及非法/截断字符进行正式模块测试；原本机 HTTP 分片复现现在通过 |

热键运行状态新增只读命令：`get_hotkey_status → { activeHotkey: string | null, error: string | null }`。设置页显示实际生效的键，并在加载/保存中禁用重复操作。启动遇到损坏热键时尝试临时默认键；默认键仍不可用则保留应用、托盘和设置窗口，不覆盖原文件。

原子保存使用与目标文件同目录的新临时文件，完整写入并同步后通过 Windows 文件替换提交。没有引入额外 npm 包或 Rust 包依赖，只启用了现有 windows 依赖的文件系统 API feature。

## 测试证据

- [修复前正式模块测试](evidence/fix-regressions-before.txt)：首批 15 项中 3 项通过、12 项失败，失败包括旧键/旧配置丢失、启动无回退、UTF-8 分片乱码及截断字符未报错。
- [修复后正式模块测试](evidence/fix-regressions-after.txt)：补充写盘与补偿检查后 **20 项通过，0 失败**。测试位于正式 Rust 模块，不依赖复制源码。
- [正式构建日志](evidence/fix-release-build.txt)：TypeScript 和 Vite 构建通过，Tauri release 构建通过；未打 MSI/NSIS 包。
- [启动状态](evidence/fix-native-start.txt)：页面为 `http://tauri.localhost/`；配置和实际绑定均为 `Ctrl+Shift+T`，热键错误为空。
- [首次重选](evidence/fix-reselect-first.txt)：只剩 main、overlay，`overlayVisible=true`。
- [OCR 后状态](evidence/fix-ocr-first.txt)：popup 已重建，overlay 隐藏。该次坐标输入选中了背景文字，而非预定设置页标题，所以只用来证明 OCR→浮窗流程完成，不用来宣称预定区域识别准确。
- [重复触发重选](evidence/fix-reselect-double-click.txt)：同一事件轮对真实按钮调用两次 click；最终只有 main、overlay，框选层可见。
- [Esc 处理](evidence/fix-escape.txt)：真实 overlay 键盘处理器执行后，`overlayVisible=false`，热键仍有效。

本机原生窗口自动化遇到“窗口已最小化”“无法获取坐标”的工具限制；部分 CDP 坐标点击也发生页面切换干扰。最终重复点击及 Esc 检查采用真实 WebView 的 DOM 按钮/键盘事件，调用原组件处理器和真实后端命令；不把这部分称为完整的物理鼠标、物理键盘回归。原生桌面工具失败记录不作为产品失败或测试通过的证据。后台打开失败的所有系统原因没有在真实桌面逐一注入；保留旧浮窗及前端错误恢复路径经过代码检查。
