# STOR 双界面暖白风格改造计划

日期：2026-10-27。状态：计划，尚未实施界面改造。

## 目标与依据

以用户提供的双界面参考图为视觉依据，将翻译浮窗与设置窗口改为暖白背景、墨绿色主操作、细描边、低饱和辅助色的工具界面。保留参考图的信息顺序与主要布局，按已确认的适中窗口尺寸压缩留白。

- 翻译窗默认内容尺寸约 **560×820** 逻辑像素。
- 设置窗默认内容尺寸约 **800×820** 逻辑像素。
- 以上是目标尺寸，创建和显示窗口时须受当前显示器工作区约束；高 DPI、小屏幕下缩小到可用范围，内容滚动。
- 本轮交付为改造计划；实现阶段沿用现有 React 19、TypeScript、Tauri 2 和 Rust。

## 现状核对

已读取当前源码，不以历史截图或旧测试数量作为当前验证结论：

| 部位 | 当前实现 | 改造方向 |
| --- | --- | --- |
| 翻译浮窗 | 默认 400×520，暗色，整个页面滚动 | 扩大默认尺寸，暖白，标题栏与底栏固定 |
| 翻译触发 | 点击语言按钮直接调用翻译 | 按参考图拆成语言选择与“翻译”按钮 |
| 结果区域 | 有结果才出现 | 译文、释义区域始终有明确位置和空状态 |
| 英文查词 | 输入框外另有可点击分词区域 | 保留点词能力，放入输入区域所属的紧凑辅助区，仅英文内容时出现 |
| 复制入口 | 两个复制按钮集中在底部 | 分别移到译文、释义区域右上角 |
| 设置窗口 | 默认 520×720，原生标题栏，字段纵向排列 | 统一自定义标题栏，三个设置分组，宽窗双列 |
| 置顶 | 翻译窗创建时始终置顶 | 增加有实际开关行为的图钉按钮 |

工作区已有多处未提交的前后端改动。实现前需基于当前文件继续修改，并记录本次涉及的变更，避免覆盖已有工作。

## 一、统一视觉与组件

以下数值是依据参考图提出的初始值，最终以窗口实拍对照校准：

| 项目 | 初始规则 |
| --- | --- |
| 页面背景 | 暖白，约 `#F7F8F4` |
| 标题栏、底栏 | 略深暖灰，约 `#F0F2ED` |
| 表单表面 | 白色；结果和空状态使用更柔和的浅灰绿 |
| 主色 | 墨绿，约 `#207F6C`；按钮文字与底色需验证对比度 |
| 主要文字 | 深灰绿，约 `#293733` |
| 次要文字 | 降低强调但保证可读；不直接照搬图中偏淡的小字 |
| 描边 | 1px 浅灰绿；聚焦时使用清晰绿色焦点环 |
| 圆角 | 窗口约 16px，卡片约 12px，输入与按钮约 6–8px |
| 字体 | 沿用 Segoe UI / Microsoft YaHei 系统字体 |
| 字号 | 正文约 14px，辅助文字 12–13px，分区标题 18px，设置标题 24–26px |
| 控件高度 | 输入与主要按钮约 40–44px |
| 间距 | 8px 基础节奏；翻译窗左右约 24px，设置窗约 28px |
| 图标 | 统一线性 SVG；参考图的框选标记用于窗口品牌区域 |

建议提取少量共享组件：`WindowHeader`、`LanguageSegment`、`ResultPanel`、`SettingsCard`、`ToggleSwitch`。只有实际复用的结构才提取，不引入大型 UI 框架。

颜色使用 CSS 变量，限定在翻译和设置界面。共享样式变化必须检查框选层，尤其是透明背景、文字颜色与选区提示。

## 二、翻译窗口布局

从上到下：

1. **固定标题栏**：框选标记、STOR、分隔线、“翻译与查词”；右侧图钉、最小化、关闭。标题空白区域可以拖动，点击按钮不触发拖动。
2. **翻译输入区**：标题与语言提示；白底多行输入；底部左侧选词提示、右侧字数。英文内容时出现紧凑点词辅助区，保留原文编辑和中日文拖选。
3. **翻译控制行**：“翻译为”标签，下方中文 / English / 日本語分段选择，右侧独立“翻译”按钮。
4. **译文区**：标题左对齐，右侧“复制译文”；初始有空状态，运行时显示流式结果，缓存和错误反馈靠近结果。
5. **上下文查词区**：分隔线、标题、当前选词状态；解释语言分段选择与“查词”按钮；下方固定结构的词语释义面板，右上角复制入口。
6. **固定底栏**：左侧提示与当前实际生效的框选快捷键，右侧墨绿色“重新框选”。

行为约定：

- 语言切换只更新目标语言，点击“翻译”才提交；这是对现有操作方式的明确调整，并同步更新使用说明。
- OCR 返回后填入原文，继续按需提交翻译；选词和切换解释语言不会自动调用查词。
- 图钉默认开启，与当前置顶默认行为一致；本轮采用窗口会话状态，不新增持久化设置。
- 无原文禁用翻译，无选词禁用查词，无结果禁用对应复制。运行中提供反馈并防止重复提交。
- 复制成功后短暂显示“已复制”；复制失败显示实际失败反馈。
- 原文变化后，旧结果需清除或明确标记失效，避免让用户把旧译文当作新原文的结果；请求中的原文编辑与选词也要防止串结果。
- 输入区的语言提示与真实能力对应：OCR 按当前配置显示自动检测或指定语言，不伪造源语言检测结果。
- 底栏展示实际生效快捷键，不能始终写死默认值。

## 三、设置窗口布局

1. **固定标题栏**：共享品牌区域与“设置”，右侧最小化、关闭。
2. **页面标题**：“设置”及一句用途说明。
3. **翻译服务卡片**：标题和 API Key 配置状态；下方 API Key 输入与模型选择并排，密钥字段较宽；底部解释“留空保留，输入新密钥覆盖”。
4. **语言卡片**：默认目标语言与 OCR 语言并排，各有完整标签。
5. **框选与使用卡片**：快捷键说明在左、输入在右；下方冻结画面和翻译缓存开关并排，带简短解释。
6. **浅绿提示区**：提示可通过快捷键或系统托盘使用框选翻译；内容依据当前可用状态显示。
7. **固定底栏**：左侧显示编辑、保存或错误反馈，右侧“保存设置”。

行为约定：

- 配置加载完成前禁用提交；保存期间禁用重复提交并显示“保存中…”。
- 保留现有密钥安全存储方式，不回显旧密钥，空输入保留旧值。
- 保留快捷键注册失败反馈与现有保存事务处理；不得仅因按钮被点击就显示保存成功。
- 保存成功、失败、快捷键不可用分别提供明确文字反馈；不能仅以颜色区分。
- 窄窗口时双列字段和开关区改为单列，按视觉顺序保持键盘焦点顺序。

## 四、窗口与适配

- 设置窗口关闭原生装饰栏，避免自定义标题栏与系统标题栏重复；补齐拖动、最小化、关闭行为。
- 保留当前生命周期：设置关闭后隐藏，翻译窗最小化与关闭分别沿用现有行为；完整退出仍由托盘提供。
- 为图钉补齐 Tauri 置顶权限及状态读取；验证切换成功后再更新按钮状态。
- 设置窗双列切单列的断点初拟约 680px，以真实卡片内容是否拥挤校准。
- 翻译窗默认保持纵向两大区，优先减少留白；长英文、长译文和错误文本可换行，无横向滚动。
- 标题栏、底栏不随正文滚出；正文留出完整可滚动空间。长结果优先参与正文滚动，避免多个小滚动容器相互嵌套。
- 检查 100%、125%、150% Windows 缩放；窗口尺寸和位置依据显示器工作区计算，不能直接把参考图像素作为屏幕物理像素。

## 六、验收清单

- 默认尺寸下，两窗结构、暖白墨绿配色、卡片层次及操作位置与参考图一致；辅助文字清晰可读。
- 初始空白、OCR 已填入、英文点词、中日文拖选、翻译与查词进行中、成功、缓存、失败、复制完成均有明确状态。
- 长文本、中英日混排、长错误信息不会撑破卡片或遮住底栏。
- API Key 已配置与未配置、保存中与保存失败、快捷键冲突都有对应反馈。
- 图钉真实切换置顶；标题栏能拖动；最小化、关闭、托盘再次打开与当前产品行为一致。
- 已选尺寸、窄窗、100% / 125% / 150% DPI 下不出现横向滚动或不可达按钮。
- 按 Tab 可依次操作所有控件，焦点可见；图标按钮具有可访问名称；开关及分段选择支持键盘。
- 执行 `npm.cmd run build`，并对涉及的窗口及配置行为运行已有相关测试；测试数量以本次运行结果为准。
- 首轮批量检查两窗、尺寸和状态，集中修复后再做一轮确认。
- UI 验证使用固定样例与模拟流式数据，避免产生付费模型请求；模拟验证与真实窗口验证分别记录。
