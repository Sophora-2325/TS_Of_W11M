# STOR

Win11 游戏屏幕 OCR 翻译工具。在玩未汉化外文游戏时，通过快捷键框选屏幕文字，本地识别后使用云端或本地模型翻译为中文、英文或日文。

## 功能特性

- **全局快捷键** — 默认 `Ctrl+Shift+T` 唤起框选层，可在设置中自定义
- **屏幕框选 OCR** — 拖选任意区域，使用 PP-OCRv6 small 在 CPU 本地识别文字（支持中 / 英 / 日混排）
- **语种选择翻译** — 先选择目标语言，再点击「翻译」调用 API，避免误触消耗 Token
- **多方案翻译服务** — 支持 DeepSeek、自定义 OpenAI 兼容服务，以及 LM Studio / Ollama 本地服务；可切换流式或一次性输出
- **直接运行 GGUF** — 复用已有模型文件，或确认后下载推荐模型；STOR 自动启动隐藏推理引擎，无需打开 LM Studio
- **原文可编辑** — OCR 有误时可手动修正后再翻译
- **画面冻结** — 框选时可冻结当前显示器画面，避免游戏画面移动影响选区
- **翻译缓存** — 相同原文 + 语种的结果本地缓存，减少重复请求
- **系统托盘** — 左键打开翻译窗口；右键可打开设置或退出
- **安全存储** — API Key 保存在 Windows 凭据管理器，不写入配置文件
- **上下文查词** — 长句中选中词语，由当前方案的模型结合整句解释词义（中 / 英 / 日可选）

## 系统要求

- Windows 11
- [WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)（Win11 通常已预装）
- 可用的 OpenAI 兼容服务，或兼容的 GGUF 模型；直接运行 GGUF 支持 Windows x64，GPU 加速需 Vulkan 驱动，也可选仅 CPU

## 安装

从 Release 或本地打包产物安装：

| 格式 | 路径 |
|------|------|
| MSI 安装包（需另行构建） | `src-tauri/target/release/bundle/msi/STOR_0.1.0_x64_en-US.msi` |
| NSIS 安装程序 | `src-tauri/target/release/bundle/nsis/STOR_0.1.0_x64-setup.exe` |

安装后应用会在系统托盘运行，并**自动打开翻译浮窗**（空白输入界面），不会自动弹出设置窗口。

PP-OCRv6 small 的当前交付使用 NSIS 安装包；旧 MSI 产物不代表已包含新 OCR 组件。

## 快速上手

1. **配置翻译服务** — 右键托盘图标 → **打开设置**，编辑或新增连接方案，填写地址、模型及认证信息，点击「设为当前」并保存
2. **框选翻译** — 游戏中按 `Ctrl+Shift+T`，在屏幕上拖选要翻译的文字区域；按 `Esc` 取消
3. **手动输入** — 启动后或左键点击托盘图标，在翻译浮窗中输入或粘贴文字
4. **选择语种并翻译** — 在「翻译为」中选择 **中文** / **English** / **日本語**，再点击 **翻译**
5. **查看译文** — 等待流式输出完成。可拖动标题栏移动窗口，用标题栏图钉切换置顶，或在译文区点击 **复制译文**、在底栏点击 **重新框选**

> OCR 识别不准时，可直接在「原文」文本框中修改。修改原文会清掉旧译文，需再次点击 **翻译**。

### 直接运行 GGUF（无需打开 LM Studio）

1. 新增连接方案，将服务预设设为「本地 GGUF 模型（STOR 自动运行）」。
2. 选择「使用已有模型（推荐）」并选取 LM Studio 已下载的 `.gguf` 文件。只记录路径，不复制、不移动、不重新下载模型。
3. 没有模型时选择「下载模型」，查看推荐模型、文件大小及保存位置，确认后下载。目标位置已有对应文件时可校验后直接复用，不覆盖原文件。
4. 点击「设为当前」及「保存设置」。也可先点击「测试生成」，使用草稿测试而不保存。
5. 首次生成时，STOR 从安装包自带的 llama-server 压缩包离线校验、解压引擎，再加载模型，无需下载引擎。已有可用部署会直接复用。

模型文件与推理引擎是两份独立资源：已有 Hy-MT2 可以直接复用；约 31 MiB 的引擎压缩包已随安装包附带。模型准备好后，本地推理无需联网。
保存设置或打开 STOR 不会提前加载模型。后续恢复已保存的模型路径，不重复询问，设置中可「更换模型」。
默认使用 Vulkan GPU 加速，失败时可手动改为仅 CPU；高级设置默认上下文长度 4096。
切换到云端并保存后，当前本地请求完成再释放模型；关闭窗口保留托盘，托盘「退出 STOR」才关闭它启动的引擎。
第一版固定 llama.cpp b11669；仅支持该引擎兼容的文本 GGUF。Hy-MT2 擅长翻译，查词解释能力需单独判断。

设置中的引擎维护立即生效，无需保存设置：

- **恢复内置引擎**：从安装包自带资源离线恢复。
- **删除引擎**：等待当前本地请求结束后，移除运行副本和下载缓存；不删除 GGUF 模型或安装包内置恢复包。删除后暂停本地推理，重启也不会自动恢复。
- **重新下载**：明确联网重新获取同一固定版本，完成校验后再替换；失败时保留旧引擎。删除后只有手动恢复或重新下载才重新启用。

内置资源缺失或损坏时，请修复安装或在设置中手动重新下载；普通翻译不会自动联网下载引擎。

### 接入 LM Studio / Ollama 本地服务

1. 在 LM Studio 或 Ollama 下载并运行模型，启动本地 HTTP 服务；此模式由外部软件管理推理进程。
2. 在 STOR 设置中新增方案，选择对应预设。LM Studio 默认地址为 `http://127.0.0.1:1234/v1`，Ollama 为 `http://127.0.0.1:11434/v1`，默认无认证。
3. 点击「获取模型列表」选择可聊天的模型，或手动填写服务显示的模型标识；列表中出现不代表模型已经加载。
4. 点击「测试生成」检查当前草稿。测试只发送固定短句，云端服务可能计费；它不会保存设置或发送用户原文。
5. 点击「设为当前」及底部「保存设置」。翻译和查词均使用此方案，重启后保留选择。

基础地址保留自定义路径，不自动补 `/v1`；不要填入 `/chat/completions` 或 `/models`。
高级设置可调整流式输出、5～600 秒超时和两项提示词；`{{language}}` 替换为目标语言。
密钥按方案独立保存，留空保留，也可显式清除。更换地址后必须重新输入、清除或明确选择沿用原密钥。
专用翻译模型不一定擅长查词解释，可使用通用指令模型兼顾两项功能。

### 上下文查词

在翻译浮窗中，除整句翻译外，还可以查询句中某个词在语境下的含义：

1. **英文**：在原文下方的点词区单击单词，或在原文框中拖选
2. **中文 / 日文**：在原文框中拖选词语或短语
3. 在「上下文查词」区域选择 **解释语言**（中 / 英 / 日）
4. 点击 **查词**，在「词语释义」中查看结合整句的语境释义；复制按钮位于该区域右上角

> 查词与整句翻译使用独立的 API 请求；相同词语的释义会命中本地缓存。

## 使用场景

本工具主要面向 **无法复制文字** 的场景，例如：

- 未汉化的 PC 游戏对话、菜单、任务提示
- 全屏 / 无边框窗口游戏中的 UI 文字
- 图片形式的界面文字

## 设置说明

| 选项 | 说明 | 默认值 |
|------|------|--------|
| 连接方案 / 当前方案 | 保存多组地址、模型及认证，翻译与查词共用当前方案 | DeepSeek |
| API Key | Bearer 方案独立保存密钥，本地服务可无认证 | 未配置 |
| 快捷键 | 唤起框选的全局热键 | `Ctrl+Shift+T` |
| 默认目标语言 | 翻译浮窗默认高亮的语种 | 中文 |
| OCR 模型 | PP-OCRv6 small，自动识别中 / 英 / 日混合文字 | 本地 CPU |
| 模型标识 | 自由填写或从服务的模型列表中选择 | `deepseek-chat` |
| 高级设置 | 流式输出、超时、翻译与查词提示词 | 流式 / 120 秒 |
| 框选时冻结画面 | 冻结当前显示器截图作为框选底图 | 开启 |
| 启用翻译缓存 | 缓存相同原文的翻译结果 | 开启 |

## 数据存储

| 类型 | 位置 |
|------|------|
| 用户配置 | `%APPDATA%\STOR\config.json` |
| API Key | Windows 凭据管理器（服务名 `stor`） |
| 推理引擎 | `%LOCALAPPDATA%\STOR\engines\llama.cpp\b11669-vulkan-x64` |
| 下载模型默认位置 | `%LOCALAPPDATA%\STOR\models`，可更改；导入模型保留原位置 |

## 开发与构建

### 环境依赖

首次开发或构建前，安装 [uv](https://docs.astral.sh/uv/) 并运行 `npm run ocr:prepare`。
该命令会创建独立的 Python 3.12 构建环境、下载并校验官方模型、打包 OCR 子进程。
发布包自带运行环境，最终用户无需安装 Python，也无需 Windows OCR 语言包。
模型部署、协议、构建命令与验证边界见 [本地 OCR 实现说明](docs/ocr-v6-local.md)。
构建前还须按 [内置引擎资源说明](src-tauri/resources/llama.cpp/README.md) 准备固定 ZIP，并运行 `npm run engine:check`。发布构建会同时检查 OCR 和引擎资源，缺失或校验失败时停止。

- [Node.js](https://nodejs.org/) 20.19+（20.x）或 22.12+
- [Rust](https://rustup.rs/)（rustup）
- [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) — 勾选「使用 C++ 的桌面开发」

### 本地开发

```powershell
git clone https://github.com/Sophora-2325/TS_Of_W11M.git
cd TS_Of_W11M/STOR-Windows
npm ci
npm run ocr:prepare
# 按上方说明准备固定的 llama.cpp ZIP 后检查资源。
npm run ocr:check
npm run engine:check
npm run tauri -- dev
```

### 打包发布

```powershell
npm run tauri -- build --bundles nsis
```

产物输出目录：

```
src-tauri/target/release/bundle/
└── nsis/STOR_0.1.0_x64-setup.exe
```

## 技术栈

- **框架** — [Tauri 2](https://v2.tauri.app/) + [React 19](https://react.dev/) + [TypeScript](https://www.typescriptlang.org/)

## 常见问题

**Q: 框选后没有识别出文字？**

尝试缩小选区、使用更清晰的文字画面，或在翻译浮窗中手动输入原文。当前使用统一多语种模型，无需安装 Windows OCR 语言包；模型缺失时请修复安装。

**Q: 全屏游戏中快捷键无反应？**

确认 STOR 已在托盘运行，且快捷键未与游戏冲突。可在设置中更换热键，或通过托盘菜单「框选翻译」触发。

**Q: 翻译失败提示 API Key 相关错误？**

请检查当前方案的认证方式、API Key 和服务账户额度；本地无认证服务无需填写密钥。

**Q: 如何完全退出？**

关闭翻译浮窗或设置窗口不会退出应用。点击右上角 **−** 可最小化到任务栏（保留内容，点击任务栏图标恢复）；完全退出请右键托盘 → **退出 STOR**。

**Q: 查词时没有反应？**

请确认已选中词语（英文可单击分词，中日文需拖选），并且当前连接方案可生成内容。
